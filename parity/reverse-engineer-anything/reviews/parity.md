I've read the spec, ledger, fixtures, SKILL.md, references, the lib code, and all 14 test files, and run the suite (81/81 pass) plus the port CLI against the fixture target. Findings, most important first:

## Findings

**1. `ENV-001` "exact key set" is self-weakened — the reference `vocabulary` key is deleted before comparison.** CONFIRMED
`skills/reverse-engineer-anything/tests/envelope.test.mjs:35` strips the fixture's top-level `vocabulary` key (`const { vocabulary: _vocabulary, ...fixtureEnvelope } = fixture`) before asserting key equality, and `createEnvelope` (`scripts/lib/envelope.mjs:95-115`) never emits `vocabulary`. The reference envelope (`fixtures/reference/rea-6.4.0-analyze-javascript-application.json`) has 16 top-level keys including `vocabulary` (nodeKinds/edgeRelations/observationProperties); the port emits 15. The spec (`spec.md:89-97`) claims "the exact key set," and the port omits a real key without listing it as a deviation. Smallest fix: either emit a `vocabulary` block, or change the spec to list `vocabulary` as an intentional deviation and stop calling it "exact."

**2. Twelve reference capabilities visible in the fixtures are neither implemented nor declared out of scope.** CONFIRMED
`fixtures/reference/rea-6.4.0-capabilities.json` lists 18 operations, all `available: true` on the reference host. `decode_interface_builder`, `demangle_swift`, `extract_artifact`, `inspect_asset_catalog`, `inspect_keyed_archive`, `inspect_macho`, `inspect_managed_native_boundaries`, `inspect_native_dispatch_metadata`, `inspect_plist`, `inspect_signature`, `list_architectures`, and `trace_dylib_resolution` appear in neither `spec.md:52-65` (out of scope), the ledger, nor `capabilities.mjs` (IMPLEMENTED_OPERATIONS/UNAVAILABLE_OPERATIONS). A reader of the ledger would conclude the boundary is complete; it isn't. Smallest fix: add a NOT APPLICABLE row (or a "macOS-native inspection family" out-of-scope entry) covering these 12.

**3. `statistics` fields are computed differently from the reference and not documented.** CONFIRMED
`scripts/lib/formats/javascript.mjs`: `visited_ast_nodes` is the *token* count (`:166`, `+= tokenized.tokens.length`), not AST nodes (reference uses a real parser: 239 nodes vs 34 observations on its tree); `findings` is total observations (`:216`) while the reference's `findings` (23) equals observations minus `javascript-module` observations (34−11); `modules` is resolved-specifier count (`:355`, 3 on the port's tree) while the reference reports 0 with resolved modules present; `text_bytes_read` double-counts `package.json` (read once in `readPackageJson:130` and again in `extractFiles:159`). None of this is in `decisions.md`. Smallest fix: document the semantic differences in `decisions.md` (and fix the `package.json` double-count), or compute to match.

**4. Four reference summary fields are hardcoded to 0, never computed.** CONFIRMED
`scripts/lib/formats/javascript.mjs:542-547` sets `ambiguous_renderer_transmissions`, `sender_validation_observations`, `utility_processes`, `resolved_utility_entrypoints` to literal `0`. The reference computes these from the graph; a target with `utilityProcess.fork()` or a sender-validated handler would report non-zero there but 0 in the port, silently. The lexer has no support for these constructs (grep confirms no `utility`/`sender` handling outside these lines). Smallest fix: either compute them or emit the fields only when support exists, and record the gap.

**5. `OBS-002`'s acceptance test cannot fail, and the analyzer contradicts the spec's own wording.** CONFIRMED
`tests/envelope.test.mjs:144-156` only exercises the `observation()` helper with a hardcoded `state: 'inferred'`; it never runs the analyzer. The analyzer (`javascript.mjs:338`) emits `state: 'observed'` for any *resolved* specifier, which matches the reference fixture (7 resolved `javascript-module` observations are `observed` with `ast-static-analysis`) but directly contradicts `spec.md:158-168` ("Syntax read from an artifact is `inferred` — never `observed`"). Smallest fix: reconcile the spec text with the reference (resolved module references are `observed`), and make the test assert the analyzer's actual state choices.

**6. `NOT APPLICABLE` reasons cite evidence that does not contain the claim.** CONFIRMED
`ledger.json:686-692` (CAPTURE-001), `:702-706` (WASM-001), `:718-721` (SQLITE-001) cite "REA-MCP tools/list + REA-CLI capabilities," but the captured fixtures contain none of `inspect_pcap_capture`, `inspect_packet_capture`, `decode_signal_recording`, `inspect_wasm_artifact`, or `inspect_sqlite_database`, and no mention of "TShark 4.x", "sigrok-cli 0.7.2", or "WABT 1.0.42" anywhere in `tools.json`/`cli-help.txt`/`capabilities.json`. The specific prerequisites are asserted as verified when the cited evidence doesn't support them. Smallest fix: cite the actual source (REA docs, if that's where they come from) or soften to "declared unavailable; prerequisites not independently verified here."

**7. The summary view shape diverges from the reference fixture without note.** CONFIRMED
`fixtures/reference/rea-6.4.0-analysis-view-summary.json` nests the producer summary under `normalized_result.summary.electron`, carries `statistics`, and a `coverage` block with `application`/`semantic` families. `scripts/lib/views.mjs:51-62` (`summarize`) flattens the producer summary, adds `operation`/`subject`/`statistics`/`limitations`, and puts no `coverage` inside `summary` (coverage is a sibling at `:33`). Spec `VIEW-001` (`spec.md:259-266`) even says "`summary` carrying ... a coverage block," which the port doesn't do. Smallest fix: record the shape deviation in `decisions.md`, or match the reference's `electron`/`coverage.application`/`coverage.semantic` structure.

**8. `SKILL-005`/`SKILL-006` are marked VERIFIED against frozen transcripts that cannot fail.** CONFIRMED
`ledger.json:646-662` names `fixtures/e2e/pi-skill-load.txt` and `pi-install-cycle.txt` as the acceptance test. These are static 7- and 24-line transcripts, not re-runnable checks; a regression in skill loading or `pi install` would not be caught. `skill.test.mjs` only runs `parseFrontmatter` (SKILL-001), not a real session. Smallest fix: add an automated test that invokes `pi -p --no-session --skill <dir>` (or at least relabel these as evidence captures, not acceptance tests).

**9. `VIEW-001`'s "producer is not re-run" assertion is vacuous.** CONFIRMED
`tests/view.test.mjs:61-65` declares `let producerRuns = 0`, calls `buildView`, then `producerRuns += 1` and asserts `=== 1` — a hardcoded self-consistency check that passes regardless of whether the producer ran. It does not (and cannot, without instrumentation) verify the producer wasn't re-executed. The rest of the test asserts real things, so this is a cosmetic but misleading acceptance signal. Smallest fix: drop the `producerRuns` lines, or inject a producer spy and assert it isn't called.
