  Gotchas

  • It's a comment line. # budget: … starts with #, so every parser (roleLines() in models.ts, readTable() in
    setup-tool.ts) deliberately skips it. It can never override or interact with role parsing; it's metadata about
    the last setup choice.
  • Budget never changes fan-out. List length sets panel size; aliases count as entries. If your panels feel
    small, that's the role lines, not the budget.
  • Your current file makes the budget a no-op. Every role is inherit-parent, and aliases are exempt from budget
    rewriting in all flavors. On a setup re-run, your inherit-parent choices would all be preserved while only the
    budget line itself updates.
  • Two rule files, two flavors, don't cross-read. The ~/.claude/skills workflow skills read
    ~/.claude/rules/pstack-models.md (yours: # budget: unlimited with tier slugs) — not the .cursor file. "The
    budget" means different things depending on which host you're asking.
  • The label and target decouple from reality once you hand-edit. Nothing validates that role values still match
    the recorded budget. small (medium) above a table of xhigh slugs would go unnoticed — the line is a record,
    not an invariant.
  • applyBudget() in src/models.ts has zero callers in shipped code — it's vestigial; the effort rewrite happens
    in the LLM-driven setup step, with the tool only validating slugs.
