## Settled against the pinned CLI

- Plugin `alwaysApply` rules do not reach the model in Cursor CLI. pi-pstack leaves them unwired. Exact.
- Cursor CLI's Task ignores `readonly` and `environment`. pi-pstack enforces them as a recorded stronger equivalent.
- Cursor's shell keeps cwd and exports between calls. #170 matches it.

## Open, so the release is not complete

- Cursor moves a timed-out shell command to the background. Pi kills it.
- Shell functions do not persist. A background job's `cd` does not reach the foreground shell.
- macOS readonly shell on Node earlier than 22.21: Node `fetch` to remote hosts ignores the proxy and fails.
- macOS readonly shell refuses private addresses of other hosts.
- A readonly sibling container survives a killed host Pi process.
- A wake can be sent twice after `/tree` leaves its branch before a restart. The cancellation path for wakes is untested.
- Cloud machines lack other host paths the prompt names: personal skills, Pi docs, the model rule, transcripts.
- Targets without execution: armv7, ppc64le, s390x, native x64 kernel, minimum macOS, standalone Pi, Linux bubblewrap readonly shell with shell state.
- Live Slack, webhook ingress, Benny, and hosted automation need service access.
- No image model is configured, so image generation is unverified.
- The unchanged-prompt corpus has not been rerun against the final archive.
