## Settled against the pinned CLI

- Plugin `alwaysApply` rules do not reach the model in Cursor CLI, so pi-pstack leaves them unwired. Exact. `evidence/rules-probe-2026-11-06/`
- Cursor's shell keeps cwd and exports between calls, moves a command to the background at its wait, and waits 30 s by default. pi-pstack's `bash` matches, with `timeout` in Pi's seconds.
- Cursor CLI's Task ignores `readonly` and `environment`. pi-pstack enforces them as a recorded stronger equivalent.
- `/mode` with no following message in a separate print process saves nothing, because Pi 1.5.0 writes a session file only once it holds a user or assistant message (`session-manager.js`). Within a process, or after any message, the mode persists. This is Pi's lifecycle, not a pi-pstack defect.

## Open, so the release is not complete

- Rerun corpus pairs 20 to 27 when Cursor usage resets, and extend the corpus to the remaining workflows (swarm, arena, architect, interrogate, setup-pstack, automations, Babysit, Shipping).
- On s390x, glibc creates sockets through `socketcall`, so the readonly shell refuses network connections there.
- On macOS with Node earlier than 22.21, Node `fetch` to remote hosts ignores the readonly shell's proxy.
- `bash` `timeout` is in seconds. Values of 1000 or more are refused so a copied `block_until_ms` such as 30000 cannot wait thousands of seconds; use `bash_background` with `block_until_ms` for a millisecond wait.
- Shell functions persist across bash calls (`declare -f` replay). A background job's `cd` updates the foreground session cwd (with epoch rules so a later foreground commit wins). Unexported variables and aliases still do not carry over.
- Cloud machines lack host paths outside the package: personal skills, Pi docs, and the model rule.
- A machine booted by a failed fork launch stays up until another run on it ends.
- No real-hardware run for armv7, ppc64le, s390x, or native x64 Linux. No minimum-macOS or standalone-Pi run.
- Live Slack, webhook ingress, Benny, and hosted automation need service access.
- No image model is configured, so image generation is unverified.
- Packaging dry-run for reboot survival is verified. A real reboot remains unobserved.
