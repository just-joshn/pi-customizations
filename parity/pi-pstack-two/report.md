## Implementation summary

`extensions/pi-pstack-two` is a Pi 1.1.0 package that reproduces the Cursor plugin **pstack 0.15.20** (`cursor/plugins@1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def`, MIT) and the Cursor host features its skills call:

- **Skills and resources.** All 52 pstack skills (with references, scripts, and the `poteto-help` guide pages), the `poteto-agent` and `comment-sicko` agent definitions, the dormant Benny automations, and the three `cursor-team-kit` 1.2.0 dependency skills (`deslop`, `control-cli`, `control-ui`). Vendored bytes are hash-locked to upstream; a sync script re-verifies byte equality.
- **Host mechanisms.** `/name` skill aliasing, `/mode` custom modes with branch-aware persistence and a status badge, the `Task` subagent tool (foreground and background children running `pi --mode json`, resume, depth caps, readonly, model resolution, usage accounting), `TodoWrite` with a widget, `AskQuestion` over `ctx.ui.select`, the always-applied model rule (written at a Pi path, injected into every request, with a `tool_call` guard on the Cursor path), `/loop` with agent-armed wakes, a host-map system-prompt section that translates Cursor tool names, transcript paths, and skill locations for pstack's prose, a fresh Pi-native `create-skill`, and a patched `worktree-audit.sh` that reads Pi transcripts.

Pi mechanism: one extension entry (`src/index.ts`) registering tools, commands, event handlers, and system-prompt sections; resources declared in the package `pi` manifest (`extensions` + `skills`).

## Parity status

**VERIFIED 51 · NOT VERIFIED 2 · INCONCLUSIVE 4 · NOT APPLICABLE 7** — validator-derived verdict: **NOT VERIFIED**.

Critical gaps: none of the open rows is marked critical. The two NOT VERIFIED rows and their impact:

- **TASK-017** — background subagent usage does not join the session totals. Pi 1.1.0 gives extensions a `ReadonlySessionManager` (`dist/core/extensions/types.d.ts:223`), a `Pick` over `SessionManager` that omits `appendUsage` (`dist/core/session-manager.d.ts:269`). Foreground usage is counted (TASK-014); background usage lives in the child transcript and the notification's `details.usage`. Re-confirmed against the installed Pi this session. Closes when Pi exposes a usage append to extensions.
- **TASK-019** — a readonly subagent gets no shell at all, where Cursor's readonly subagents can run non-mutating commands (`git log`, `git blame`). Pi has no read-only shell tool (its containerization docs isolate whole processes, not command effect), and a parsed allowlist would be bypassable, so the port refuses to claim that isolation. Documented in README Limits.

## Security and maintenance

- Security boundaries covered by SEC-001 and the two security review rounds: argv arrays (no shell interpolation), EPIPE-safe child stdin, bounded output via Pi's `truncateHead`, atomic record/lock writes with dead-pid takeover, depth cap enforced by env + records with resume at `max(recorded, caller+1)`, trust propagation via `ctx.isProjectTrusted()`, path canonicalization through nearest existing ancestor for the rule guard, mode entries storing validated skill names only (never raw paths).
- Boundaries the port cannot enforce (documented in README Limits): a depth-capped child can still run `bash` and start a grandchild by hand; a bash command can write the Cursor rule path the `tool_call` guard protects; the run-lock takeover has a narrow pid-reuse window; `scripts/live-e2e.mjs` intentionally exposes the real `auth.json` to the model under test.
- Maintenance: upstream resync is `node scripts/sync-upstream.mjs --source <checkout>` with `--check` as a gate; `upstream.lock.json` pins per-file hashes. `decisions.md` §copies lists each place the port mirrors Pi-private logic (e.g., `getSessionStats` usage summation) with the condition for deleting the copy. Pi API drift watch: `ReadonlySessionManager.appendUsage` (TASK-017 closure), any read-only shell mechanism (TASK-019).
