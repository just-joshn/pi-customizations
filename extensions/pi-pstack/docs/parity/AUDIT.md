# Native parity audit contract

The reference is `docs/parity/reference/pstack-architecture-reconstruction.md`, vendored from `~/Documents/DOCS/pstack-architecture-reconstruction.md` so external file churn cannot break the gate. It describes the Reference plugin pstack, the team-kit skills, and the Reference built-ins they use. This package must give each described behavior a native Pi equivalent. The gate `scripts/check-native-parity.mjs` decides completion. It re-executes every check you write, so a check is either true on disk or it fails.

The clause files under `docs/parity/clauses/` were rebuilt for the vendored revision, split into four slices `s1` to `s4`. FIX.md and REAUDIT.md describe an earlier revision whose reference document no longer exists and whose slice files were removed.

## Your write scope

Edit only `docs/parity/clauses/<your slice>.json`. Do not edit this file, the gate, other slices, source, tests, skills, or generated resources. Report needed code changes as `gap` clauses.

## The question for every clause

What does Pi do about this, and where is that on disk? Answer from the native files, not from the reference, earlier audit documents, or package prose under `docs/`.

- Native files are everything in this package except `upstream/`, `upstream-team-kit/`, `docs/`, `node_modules/`, and `coverage/`. That includes `skills/`, `prompts/`, `host/`, `src/`, `scripts/`, `test/`, `README.md`, and `package.json`.
- Generated resources in `skills/` and `prompts/` come from `scripts/resources.mjs` and `docs/resource-map.json`. When one drops an obligation, the fix belongs in the generator. Name the transform in the gap note.
- `src/host.ts` is the host contract injected each turn. It maps Reference facilities (Task parameters, cloud agents, `/loop`, subscriptions, AskQuestion, transcripts, the model rule) to Pi tools.
- Preserved sources are `upstream/`, `upstream-team-kit/`, `~/.upstream/skills-reference/`, and `~/src/experiments/plugins/` (a git repository whose history includes the cited commits).

## Clause shape

```json
{ "id": "L1187.2", "lines": [1187, 1187], "requirement": "...", "kind": "behavior", "runtime": true, "verdict": "verified", "checks": [ ... ], "note": "..." }
```

- `id` is `L<first line>.<n>`, unique in the slice.
- `lines` is the reference span. Every non-blank content line in your slice must fall inside some clause. Headings, blank lines, table rules, and fence markers are exempt. Fenced diagram and code text is not exempt.
- The seeded clauses were split mechanically into sentences. Some are fragments, some are missing, and their `requirement` text may be truncated. Rewrite, split, merge, or add clauses so that each states one checkable requirement. Keep `lines` accurate.

## Kinds

- `behavior` is anything Pi must do, say, or provide: workflow steps, skill instructions, tool semantics, script behavior, model-role wiring, packaging and discovery. A Reference facility listed in a mapping table (including the Provider CLI porting tables) is a requirement that Pi supports that facility.
- `fact` is history or provenance with no behavior for Pi: commit history, version timelines, upstream line counts, who wrote what. If a fact implies a behavior, such as "46 of 47 skills disable model invocation", split out a `behavior` clause for what Pi does.
- `defect` is a contradiction, stale reference, undefined term, or risk the reference found in pstack. Prove that it exists upstream, then show how Pi resolves it. If Pi inherits it unresolved, the verdict is `gap`.
- `index` is pure navigation: tables of contents, "see section X", "go to" tables. Requires a note.

## Verdicts

- `verified`. The native files carry the same obligation, with Reference nouns mapped to their Pi facility. A paraphrase that keeps every constraint is verified. A paraphrase that drops a constraint, a number, an ordering, a stop condition, an exception, or a forbidden action is a `gap`.
- `gap`. Pi lacks it, weakens it, or lacks a test for runtime behavior. Note format is `GAP: <what is missing>. FIX: <file or generator transform, and the test to add>.`
- `external`. Only for a live third-party service that has no credentials on this machine: Slack, Linear, Sentry, Upstream-hosted services (dashboard, Automations editor, the origin host), or the Reference Marketplace. GitHub is reachable through an authenticated `gh` and is never external. Native setup, configuration, gating, and fixture behavior around an external service are separate `behavior` clauses.
- Never use `unaudited` in your final file.

## Checks

| type | fields | holds when |
| --- | --- | --- |
| `quote` | `path`, `quote` | the native file contains the quote, whitespace-collapsed |
| `file` | `path` | the native file exists |
| `test` | `path`, `name`, optional `runner` | the named test passed |
| `source` | `path`, `quote` | a preserved source contains the quote |
| `source-file` | `path` | the preserved source file exists |
| `commit` | `rev`, optional `subject`, optional `repo` | the commit exists in `~/src/experiments/plugins` (or `repo`) with that subject substring |

- Copy quotes from the file byte for byte, at least 15 non-space characters. Quote the sentence that carries the obligation, not a heading. One quote may back at most 12 clauses.
- `behavior` needs a native check (`quote`, `file`, or `test`). Set `"runtime": true` when the clause describes something that executes (a tool, command, script, process, wake, timer, or worker). Runtime behavior also needs a `test` check.
- Test names are exact. For vitest, `name` is the describe titles and test title joined by single spaces, with `test.each` or `test.for` placeholders formatted. For the shipped helper suite, use `"runner": "bun"` and a path under `skills/poteto-mode/scripts/`, and the name is the describe titles and test title joined by spaces. For a real Pi CLI journey, use `"runner": "journey"`, `"path": "scripts/verify-journeys.mjs"`, and the exact name passed to `check(...)` in that script.
- If no test exercises runtime behavior, the verdict is `gap` with `FIX: add test ...`.
- `fact` needs `source`, `source-file`, or `commit`. `defect` needs one of those plus a native check and a note.

## Done

Run `node scripts/check-native-parity.mjs --slice <slice> --no-tests` from the package root. You are done when the only findings are `gap` and `external` clause lines. Your final message lists the counts by verdict, every `gap` id with its note, and every `external` id with its service. Do not soften a gap to make the count look better. A missing obligation found now is cheap. One hidden behind a generous verdict is the failure this audit exists to prevent.
