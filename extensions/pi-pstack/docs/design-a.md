# Candidate A: immutable upstream package plus Pi compatibility runtime

## Finding

Pstack is an instruction package, two agent definitions, executable helper scripts, documentation, and separately deployed Benny automation templates. It does not implement Cursor's Task runtime, model entitlement system, cloud agent hosting, MCP tools, or loop service. Port its complete instructions and artifacts unchanged, then implement the host capabilities it assumes using Pi's documented extension and SDK interfaces. Distinguish source parity from runtime and platform parity. A claim of unconditional 100% behavior parity would be false because several required services are absent from both repositories.

## Source-grounded package design

Vendor the complete pstack subtree at a pinned commit under `upstream/pstack/`, retaining LICENSE, README, assets, docs, scripts, tests, lockfile, automations, hidden plugin metadata, skills, and agents. Record every file's relative path and SHA-256 in a provenance manifest. Build a validation command comparing the manifest to the vendored content and checking references. Never rewrite upstream source merely to make Pi discovery convenient.

Package `pi.extensions` declares one entry. `pi.skills` declares upstream skill roots. Current Pi permits malformed skill names with warnings, but excludes skills lacking required descriptions and resolves collisions first-discovered. Upstream Poteto Mode uses `name: Poteto Mode` rather than valid lowercase hyphen spelling. Explicit `/poteto-mode` compatibility commands therefore must route by directory identity, not depend on Pi-generated `/skill:Poteto Mode`. Alternative is generated discovery wrappers referencing immutable originals; this introduces two layers and complicates `/skill:` behavior. Prefer registering commands by directory slug for every skill, while native discovery retains upstream metadata.

Each command reads the entire immutable SKILL.md, includes its absolute base directory, and submits it with the user's arguments via `pi.sendUserMessage`. Native `/skill:name` can coexist. The extension adds a short host compatibility section identifying exact path/tool translations and unavailable services. Do not summarize or replace the upstream skill instructions. Include all nested Benny skill assets, with a deliberate command namespace to avoid collisions if necessary.

Pi package peers must be `@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`, and `typebox` at `*`, only those imported. These are host packages, not normal dependencies. Existing older examples using `@mariozechner/*` and TypeBox's old package name do not describe this checkout.

## Runtime shapes

Represent session state as `{stickyModes, todos, agents}`. Agent records are discriminated states `running | settled | failed | interrupted`, each containing stable ID, agent type, chosen provider/model and reasoning, workspace, transcript location, and available final output. Keep the live AgentSession outside the durable record. Persist branch-sensitive decisions in `pi.appendEntry` and reconstruct using `ctx.sessionManager.getBranch()` on session start, switch and tree navigation. Never replay every session entry across abandoned branches.

Create no agents, timers or sockets in the extension factory. Register tools and commands there. Construct child sessions only in an invoked tool. Dispose/abort children in idempotent `session_shutdown`. Parent cancellation must reach children; never leave a background write running after the user aborts its owner without a documented independent-owner policy.

Implement Cursor-facing `Task` with documented parameters used by pstack (`subagent_type`, `prompt`, `model`, `readonly`, `run_in_background`, `environment`, `resume`). Return a stable ID immediately for background tasks. A wait/read tool reports settled output without confusing an accepted prompt with completion. Provide explicit send/steer/follow-up and cancel operations. A unified management tool can be used if compatibility text translates names exactly, but Cursor-compatible names reduce instructional drift. Resuming poteto-agent uses the existing session and preserves its conversation, rather than spawning a sibling. Agent definitions and selected skill text must be read in full before the child first runs.

SDK construction uses `createAgentSession({cwd, model, thinkingLevel, resourceLoader, sessionManager})`; current SDK additionally accepts `modelRuntime`, not old authStorage/modelRegistry factory options. `DefaultResourceLoader` accepts `additionalSkillPaths`, `extensionFactories`, `appendSystemPrompt`, and overrides. Call `await loader.reload()` before creation. Child session defaults would rediscover the parent extension and recursively spawn duplicate supervisors unless discovery is intentionally configured. Pass a small inline child extension implementing delegation and bridges, preserve trusted project context/resources, and guard instance ownership. Do not set `noExtensions` casually if that strips the user's MCP integrations; discovery must expose those extensions to children through an explicit contract.

Subscribe before `session.prompt()`. Prompt resolves when accepted work finishes including retry behavior; `agent_end` alone is insufficient. Use `agent_settled` for background completion. `session.steer`, `session.followUp`, `session.abort`, `session.waitForIdle`, and `session.dispose` are supported methods. A prompt during streaming needs an explicit queue policy. Preserve full logs by file pointer and return bounded output plus structured metadata and nested usage totals.

SDK is preferable to ad hoc subprocess JSON parsing here. Official RPC `RpcClient` is a valid alternative for isolation, but RPC commands acknowledge acceptance, not completion; it requires `agent_settled`, proper LF framing, backpressure, crash/cancel handling, and no stdout logging. Readonly child tool selection should omit mutating tools. Bash is capable of arbitrary writes, so retaining Bash while calling the agent readonly is only an instruction policy, not enforcement. Cursor's readonly MCP exclusion is platform-specific and should be disclosed.

## Models and setup

Discover actual models with `ctx.modelRegistry.getAvailable()` and use exact provider/model identity. Cursor slugs combine vendor aliases and reasoning levels, while Pi stores model and thinking separately. Build an explicit resolver returning either a proven model plus supported effort or an actionable rejection listing same-family candidates. Never interpret an unavailable Cursor model as permission to use an arbitrary default. The skill owns its specified fallback sequence. Preserve `auto` and `inherit-parent` exactly as inheritance, including duplicate aliases in panels because every seat counts.

Keep the upstream role labels and list order. Read the existing `~/.cursor/rules/pstack-models.mdc` when present for migration interoperability. A Pi-native configuration location requires an explicit compatibility mapping because the original skill writes that literal path. Could preserve that same path and inject the rule each run, but Pi users then receive writes into Cursor config. Better provide the Pi destination in the host contract and a setup tool that validates it; record this as a host-path adaptation, not byte-level source change. Budget labels and target efforts are fixed by upstream; Pi clamps effort to model capabilities, which must be surfaced in setup rather than silently claiming identical reasoning.

`AskQuestion` can wrap `ctx.ui.select/input/confirm` for TUI/RPC. These are unavailable in print/JSON. A headless invocation must return a pending-input state or throw a clear interaction requirement. Never synthesize a confirmation. Todo storage and rendering are straightforward extension state; support the list mutations the skill expects and verbatim first playbook steps.

## Sticky modes

Cursor-specific `mode: true`, `reminder`, `icon`, and `color` have no automatic Pi behavior. Parse these fields explicitly. Invoking poteto-mode sets a branch-local active mode, renders status in TUI, and appends the reminder at `before_agent_start`. An explicit off command clears it. Natural-language opt-out needs a model-visible mode tool because naive regular expressions can misinterpret quoted text and unrelated instructions. Remember to include selected mode text after compaction; durable custom entries alone do not place text in model context.

Important documentation/source mismatch: extensions.md recommends modifying structured sections through `systemPromptOptions`, but the actual current `BeforeAgentStartEventResult` type only accepts `{message?, systemPrompt?}`. Use the documented and typed message injection or append to `event.systemPrompt` in a returned `systemPrompt`. Do not invent a `systemPromptOptions` result property. `context` strips the system state; don't use it for sticky instruction placement.

## Parity boundaries that must be stated and tested

1. Cursor `environment: cloud` has no Pi SDK equivalent. Reject unless a configured cloud executor actually implements it. Never silently execute locally. Worktrees provide file isolation, not cloud infrastructure.
2. Default model slugs may be unavailable through Pi's authenticated providers. No extension can manufacture entitlement or guarantee identical provider inference. Setup can select available equivalent model identities with user control.
3. Cursor transcript paths and JSONL schemas differ. Recall/reflect/automate-me need a workspace-scoped Pi transcript adapter or explicit host translation. Do not glob all user sessions. Exporting current session history for agents avoids fiction about existing Cursor UUID paths.
4. Why's MCP discovery and child MCP access depend on installed Pi integrations. Pi core does not supply a Cursor MCP directory. Expose actual integrations, missing-source categories, and no fabricated tool access.
5. Cursor `/loop`, cloud links, worktree APIs, create-skill, cursor-team-kit deslop/control-ui/control-cli, Origin infrastructure, Slack/webhook credentials, and Benny scheduled hosted deployment are external capabilities. Preserve all instructions and installation prerequisites; they cannot be claimed implemented simply because prompts are present.
6. Identical instructions cannot guarantee identical stochastic assistant decisions, tooling conventions, safety policy, interface rendering, or model output. Tests can establish deterministic adapter behavior and asset completeness, not universal behavior parity.

## Concrete acceptance evidence

Hash inventory covers every upstream file and all relative links. Official Pi loader loads the package. Every directory command expands exact source plus arguments/base location. Native skills remain discoverable. Sticky mode survives reload and branch resume but respects off state and divergent branches. Background agent IDs persist, follow-ups retain prior child state, repeated resumes do not spawn duplicates, concurrent calls do not mix results, cancellations terminate the owned work, and shutdown is idempotent. Model resolver rejects unknown models and preserves panel order/alias counts. A tiny scripted provider can drive actual Pi sessions without paid model calls to verify runtime semantics. Finally run a real authenticated multi-agent workflow if credentials are available and label unrun external integration tests.
