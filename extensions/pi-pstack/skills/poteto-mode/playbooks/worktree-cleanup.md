### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/.pi/agent/pstack/workspaces/<workspace>/worktrees/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it. Cloud agents' machines are not git worktrees: list them with `docker ps -a --filter label=pstack.agent` and `ls ~/.pi/agent/pstack/workspaces/<workspace>/machines/`, and treat each like a worktree whose agent ID names its chat.
2. The bucket is advice, not permission. Pi sessions have no pin bit. `/resume` lists sessions and is not a protected set, so do not read it as one. Before any delete, ask the user to name the protected chats and worktrees, or show the candidate delete list and wait until the user confirms that list (principle-prove-it-works). Cross-check every candidate against that answer. The lever has marked `safe` a worktree the user still wanted, so the user's answer wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is ongoing, whether the user named it as protected, and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). An ongoing or protected chat can own arena and repro worktrees that a background subagent created beside it. Those worktrees are in use even when `/resume` does not list them as their own sessions. Pick each subagent's reasoning level (the `:<level>` suffix), and fast or standard speed when the model has a `-fast` variant, for the job, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, a worktree that is clean, merged, not in use, and on the delete list the user confirmed proceeds. `wip` and in-use pause even when they appear on that list.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, `~/.pi/agent` (old session files under `sessions/`, and `pstack/workspaces/<workspace>/artifacts/` where a workspace's generated files balloon), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, named as protected, or uncommitted work).
