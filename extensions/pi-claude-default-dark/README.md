# pi-claude-default-dark

A Pi package that makes Pi look as close to Claude Code's built-in `dark` theme as Pi's public extension mechanisms allow. It ships the `claude-default-dark` theme, display adapters that restyle Pi's own tool output and working indicator while that theme is active, and a `/claude-theme` command. It changes appearance only. Pi's prompts, tools, model requests, sessions, and keybindings stay the same.

**Parity is not certified.** The package is measured against Claude Code 2.1.323 and Pi 1.5.2 in Alacritty 0.17.0. The release gate is BLOCKED, because some Claude Code styling has no public hook in Pi. [`development/PARITY_REPORT.md`](development/PARITY_REPORT.md) lists every gate and what is still open.

## Install

```sh
pi install ./extensions/pi-claude-default-dark
```

The package is `private` until parity passes, so it is not on npm.

## Select the theme

Choose `claude-default-dark` in `/settings`, start a run with `pi --use-theme claude-default-dark`, or run `/claude-theme use`. The package never switches your theme on its own. If you pick another theme, it stays picked, and the adapters stand down.

- `/claude-theme status` reports whether Pi found the theme.
- `/claude-theme verify` checks that the active theme resolves every role to the shipped colors. It does not certify parity.

## What matches and what does not

Every theme color comes from a capture of Claude Code, or keeps Pi 1.5.2's stock dark value where Claude Code has no counterpart that the role can reproduce. [`development/theme-provenance.json`](development/theme-provenance.json) gives each role's source and evidence.

While `claude-default-dark` is active, the adapters use `pi.registerToolRenderer` and the working-indicator API to add what a theme cannot express:

- Edit diffs get Claude's line backgrounds (`#022800` added, `#3d0100` removed) across the full row, including rows that wrap, word-level backgrounds (`#044700`, `#5c0200`), colored `+` and `-` signs in Claude's order, dimmed context line numbers, and Claude's diff syntax colors on added and context lines (keywords `#f92672`, names `#a6e22e`, numbers `#be84ff`), using Pi's public `highlightCode`.
- Failed shell output is red (`#ff6b80`).
- Collapsed tool titles are gray and not bold, and file paths use the default text color.
- The working spinner and its message are Claude's orange (`#d77757`).

Pi draws these with its own components and offers no public hook to restyle them, so they still differ: syntax colors in code blocks, and inside diffs wherever Pi's highlighter classifies a token differently from Claude's (`const`, `let`, and `function` are cyan in Claude and pink here; called function names are green in Claude and plain here), link underlines, quote borders, code fences, thinking and compaction display, pickers, search highlighting, the scrollbar, and Claude-only markers such as `⏺` and `⎿`. `accent` is lavender `#b1b9f9`, because Claude Code draws Pi's accent surfaces (picker titles, selected rows) in lavender; its orange appears only on surfaces Pi does not have.

Exact colors need a truecolor terminal. In 256-color mode, Pi approximates them.

## Requirements

Pi 1.5.2. The package uses only Pi's public theme and extension APIs and declares `@earendil-works/pi-coding-agent` and `@earendil-works/pi-tui` as peer dependencies, as Pi's packaging docs require. It makes no network requests.

## Uninstall

```sh
pi remove ./extensions/pi-claude-default-dark
```

Then pick another theme in `/settings`.

## Development

`development/` holds the capture harness, the evidence, and the gate scripts. It is not part of the installed package. Run these from `development/` to rebuild the results:

| Step | Command |
|---|---|
| Lock versions and terminal | `node scripts/lock.mjs` |
| Capture both products offline | `node scripts/capture.mjs --product claude` and `--product pi` |
| Map roles, then reconcile reviews | `node scripts/crosswalk.ts`, `node scripts/reconcile.ts` |
| Generate and validate the theme | `node scripts/generate-theme.ts`, `node scripts/validate-theme.mjs` |
| Capture Pi with the package installed, then compare | `node scripts/capture.mjs --product pi --theme claude-default-dark --package .. --out pi-claude-default-dark` (also `--theme dark --out pi-dark` and the probe theme), `node scripts/crosswalk.ts`, `node scripts/compare.ts` |
| Run the runtime gates | `node scripts/g6-behavior.mjs`, `node scripts/g7-lifecycle.mjs`, `node scripts/g8-display.ts`, `node scripts/g9-robustness.mjs` |
| Write the report | `node scripts/report.ts` |

Two inputs are not regenerated by a script. `mapping-review/claude.json` and `mapping-review/gpt.json` are independent role mappings written by two model reviewers from `mapping-review/BRIEF.md`. To redo them, rerun that brief with two reviewers. G4 records the theme its themed capture used, and G6–G9 record a hash of the whole runtime package, theme included. The report marks a result stale when its recorded input no longer matches, and G0 rechecks the versions, binaries, and terminal against `reference-lock.json` on every report. G10 stays below PASS until a reviewer records `results/APPROVED-SHA256SUMS`.

Claude Code updates itself. The capture and lock scripts use the pinned 2.1.323 from `PATH` or, when `PATH` has moved on, from `~/.local/share/claude/versions/2.1.323`, and refuse to run without it.

Updating Claude Code, Pi, or the terminal invalidates the results. Rerun every step.
