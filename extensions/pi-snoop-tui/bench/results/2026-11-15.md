# Replay benchmark, 2026-11-15

## Verdict

The full extension uses less CPU than stock Pi on the replay workload: 185 ms against 262 ms of workload CPU (medians of 7 runs, set B, ranges 161..194 and 236..292). Full was lower than stock in all 14 paired rounds. The theme alone shows no measurable difference from stock. Neither configuration shows a measurable difference in idle CPU, echo latency, echo misses, event-loop delay p99, or idle terminal output.

## Setup

- Machine: Apple M4 (`sysctl -n machdep.cpu.brand_string`), 10 cores.
- Pi 1.5.2 on Node v26.13.1.
- Two sets of 7 interleaved rounds, each round running `stock`, `theme`, and `full` once in rotating order. That makes 21 runs per set and 42 in total. Every run produced a record. None failed or reported problems.
- Set A raw data: [`2026-11-15.jsonl`](2026-11-15.jsonl). Set B raw data: [`2026-11-15-b.jsonl`](2026-11-15-b.jsonl).
- Command: `python3 run.py --runs 7 --out results/<file>.jsonl`, then `python3 report.py results/<file>.jsonl`.

`uptime` before and after each set:

```
A before: 11:26  up 3 days,  5:48, 3 users, load averages: 4.05 3.15 3.13
A after:  11:32  up 3 days,  5:53, 3 users, load averages: 2.93 3.50 3.34
B before: 11:32  up 3 days,  5:53, 3 users, load averages: 2.80 3.44 3.32
B after:  11:37  up 3 days,  5:58, 3 users, load averages: 2.50 2.91 3.10
```

Other work was running on the machine, and the sandbox blocked `ps` and `top`, so the source is unknown. Set A ran under the heavier load and has the wider ranges. Interleaving gives each configuration the same noise.

**Event-loop delay p50.** Every sample includes the 10 ms sampling interval. An idle loop reads 11.0 ms in all three configurations, which is the timer's own slack. Stock reads 10.8 ms during the workload because extra wakeups let the sampler's timer fire closer to on time. Full reads 11.0 ms, the same as an idle loop. This is an inference from those numbers, not a profile. The p99, which would show blocking, does not differ.

**Idle output.** Each configuration writes one redraw within 15 ms of `agent_end` to clear the working indicator. That redraw is either about 0.8 KB or about 6 KB, in every configuration. After the first second of idle, 41 of 42 runs wrote nothing. One `full` run in set B wrote 4 bytes after the first second. That did not recur in 14 further `full` runs with `--keep-artifacts`, so the bytes and their cause are unknown.

**Limiter.** Pi's own render path bounds the workload in both configurations. `doRender` takes 87 ms inclusive in `full` and 118 ms in `stock`, and the Markdown lexer for the streaming message takes 34 to 38 ms of that. Timers come next (`processTimers`, 25 to 28 ms self). Those are the bench provider's 8 ms delta timer and the 10 ms event-loop sampler, which both configurations share.

**Why full uses less CPU.** Two stock components that `full` replaces account for the gap:

- Stock's streaming `bash` preview (`VisualLinePreview.render` and `truncateToVisualLines`) takes 24.9 ms inclusive. In `full`, the compact row's `render` (`row.ts`) takes 9.6 ms inclusive for all four tool rows.
- Stock's built-in footer `render` takes 15.1 ms inclusive, including `formatCwdForFooter`. The cached `full` footer takes no samples.

Busy JavaScript time differs by 33 ms (244 against 211 ms), and `(program)` and GC add another 9 ms. Together that covers about 42 ms of the 60 ms CPU gap between the two profiled runs. The rest is likely time on V8 and libuv helper threads, which `process.cpuUsage()` counts and a main-thread profile does not. That part is an inference.

**pi-snoop-tui share.** Functions in `pi-snoop-tui/src/` take 1.3 ms self time, 0.6% of busy time, all of it in `row.ts` `render`. No footer or chrome function appears.

## What these numbers do not cover

- Terminal paint time. Echo latency stops at the pseudo-terminal.
- Each profile is a single run. Per-function times carry about 1 ms of sampling granularity.
- The 10 ms event-loop sampler wakes Pi in every configuration, so idle CPU never reaches zero. Compare idle CPU between configurations.
